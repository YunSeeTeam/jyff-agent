# Run skill snapshots

`optimization.skillSnapshots` enables a frozen package set for each new Run. Select names (or `all`) in `skills.solver`, `skills.subagents.default`, and `skills.subagents.roles`. An explicit empty array selects no skills. A role override replaces its default. Unknown names fail before the Solver starts. The switch defaults to off; nondefault selections require it.

The host publishes `runs/<runId>/skills/` with a single directory rename after copying, hashing, and reparsing all selected packages. `manifest.json` records the expanded selections, original source paths, package hashes and container paths. Source changes detected during copying abort publication. Limits default to 2,048 files, 64 MiB for all selected packages, and depth 32. The module accepts explicit limits for controlled deployments. Symlinks and special files are rejected. This publication does not claim power-loss durability.

Solver and each SubAgent receive only their selected packages under `/workspace/.skills/<runId>/<hash>/`. Before starting or resuming a child, the host checks those workspace copies and repairs modified copies from the saved host package. Host hash failure or a missing snapshot stops recovery with `skill_snapshot_changed` or `skill_snapshot_unavailable`; current sources never silently replace a started Run's package. A published manifest whose event was lost can be validated and its event recorded again. Runs created before snapshots keep the legacy configuration with every optimization off. Father retains its existing materialization behavior.

For Compose, optionally mount `./ctf-skills:/data/.pi/skills:ro` alongside the state volume and Docker socket. Publish complete source directories, then reopen the Project or restart the backend before starting new Runs. This mount does not install executables into the Solver image.

Retain host manifests/packages and the Run's workspace namespace for every recoverable Run. There is no automatic cleanup or global deduplication. Before manual deletion, list the intended Run directories, verify the Runs are terminal and explicitly no longer recoverable, and check no active Run references them. Delete only those audited Run packages and matching workspace namespaces together; keep other Runs' files. Existing Project reset/delete remains an explicit operation that removes that Project's retained data.
